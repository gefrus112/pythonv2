Documentation

Everything you need to get Python v2 running: on your desktop, in VS Code, in a dev container or Codespaces, or in any code editor you already love. Then the whole language and PyHope game engine, on one page. Want more? Read the 50-topic field guide. New to Python v2? Start the tutorial — 10 runnable lessons.

01 Install — Desktop

Python v2 has no dependencies and no install step. If you have Python 3.10+ and Git, you're done. Works on macOS, Linux, Windows (native or WSL), and a fridge with a shell.

Step 1 — check Python 
python3 --version    # need 3.10 or newer
git --version
Step 2 — get the runtime 
git clone https://github.com/gefrus112/pythonv2
cd pythonv2
Step 3 — verify it works 
python3 -m pyv2 --version
# Python v2 1.1.0

python3 -m pyv2 examples/hello.pyv2
# Hello, World!
# 2 + 2 = 4
Step 4 — run the test suite (optional, 1 second) 
python3 -m unittest discover -s tests -t .
# ... OK

Command line

CommandWhat it does
python3 -m pyv2 script.pyv2Run a program
python3 -m pyv2 -c 'print(42)'Run a one-liner
python3 -m pyv2Start the REPL (... continues blocks)
python3 -m pyv2 --versionPrint the version
python3 -m pyv2 --helpShow usage

Windows notes

  • If python3 is not found, try py -m pyv2 script.pyv2.
  • WSL is the smoothest path: install Ubuntu from the Microsoft Store, then follow the three steps above.

02 VS Code

The repository ships ready-made VS Code config in .vscode/ and a language extension in editors/vscode/ for syntax highlighting of .pyv2 files.

Quick start (run & debug your code)

  1. Open the pythonv2 folder in VS Code (File → Open Folder…).
  2. Open any .pyv2 file, e.g. examples/fib.pyv2.
  3. Press Ctrl+Shift+B (macOS: Cmd+Shift+B) — the default build task runs python3 -m pyv2 on the current file.
  4. Output appears in the Terminal panel. That's it.

The included .vscode/tasks.json defines two tasks: Run Python v2 file (default build) and Python v2 REPL. The included .vscode/settings.json associates *.pyv2 with the pyv2 language.

Syntax highlighting (the bundled extension)

  1. Copy the extension folder into your VS Code extensions directory: 
    # macOS / Linux
cp -r editors/vscode ~/.vscode/extensions/pyv2-0.1.0

# Windows (PowerShell)
Copy-Item -Recurse editors/vscode "$env:USERPROFILE\.vscode\extensions\pyv2-0.1.0"
  2. Restart VS Code (or run Developer: Reload Window).
  3. Open any .pyv2 file — keywords, strings, f-strings, numbers and comments are now colored.

Prefer the marketplace workflow? Pack it once with the vsce tool and install the VSIX:

cd editors/vscode
npx @vscode/vsce package        # builds pyv2-0.1.0.vsix
code --install-extension pyv2-0.1.0.vsix

Alternative: Code Runner

If you use the popular Code Runner extension, add this to your user settings.json and press Ctrl+Alt+N to run:

{
  "code-runner.executorMap": {
    "python": "python3 -m pyv2"
  },
  "code-runner.fileDirectoryAsCwd": true
}

03 Dev Containers & GitHub Codespaces

Opening the repo in a dev container (VS Code or Codespaces) gives you a ready environment in seconds — Python preinstalled, tasks wired, tests passing. The config lives in .devcontainer/devcontainer.json (that's the ".dev" part).

VS Code Dev Containers

  1. Install Docker and the Dev Containers extension (ms-vscode-remote.remote-containers).
  2. Open the repo folder, then run Dev Containers: Reopen in Container from the Command Palette (Ctrl+Shift+P).
  3. First boot pulls the Python image; after that everything is instant.
  4. Run python3 -m pyv2 examples/hello.pyv2 — or just hit Ctrl+Shift+B.

GitHub Codespaces

  1. On GitHub, open the repo → Code → Codespaces → Create codespace on main.
  2. VS Code opens in your browser with the dev container already built.
  3. Everything from the desktop guide works identically inside it.

The container runs python3 -m unittest discover -s tests -t . at build time, so you always start from a green suite.

04 Any Other Code Editor

Python v2 is just text plus a CLI. Any editor that can run a shell command can run it. The universal recipe:

  • Coloring — associate *.pyv2 with Python syntax. It's close enough (and free).
  • Running — bind a build/run command to python3 -m pyv2 "$file" with the working directory set to your project.
  • Formatting — 4 spaces, one statement per line, blocks end with end. Your formatter can't break it. That's the point.

Sublime Text

Tools → Build System → New Build System…
{
    "cmd": ["python3", "-m", "pyv2", "$file"],
    "selector": "source.python",
    "working_dir": "$file_path"
}

Vim / Neovim

" in init.vim / .vimrc
autocmd BufNewFile,BufRead *.pyv2 set filetype=python
autocmd FileType python nnoremap <F5> :w<CR>:!
    \python3 -m pyv2 %<CR>

JetBrains (PyCharm, IntelliJ)

  1. Settings → Editor → File Types → add *.pyv2 to the Python type.
  2. Settings → Tools → External Tools → add a tool with program python3, arguments -m pyv2 $FileName$, working directory $FileDir$.
  3. Bind it to a shortcut under Settings → Keymap.

Notepad++

Run → Run… (F5) with:

cmd /c python3 -m pyv2 "$(FULL_CURRENT_PATH)"

05 Sudbury Desktop Launcher

Python v2 1.1 ships with its own desktop workspace. It is implemented with Python's standard-library tkinter toolkit—no Electron, pygame, browser shell, subscription, or account.

Open the app

# after running install.bat or install.sh:
pyv2-launcher

# always works, even if the command folder is not on PATH:
python3 -m pyv2.launcher

Windows also gets a Desktop shortcut. macOS gets ~/Applications/Python v2 Sudbury.app. Linux gets an app menu entry. If your Linux distribution separates tkinter, install its python3-tk package; the language CLI still works without it.

App layout

Docs & LearnTutorial, 50-topic guide, reference, and CubeCometYT milestone

Build a website with Python v2

  1. Open New Project and choose Website.
  2. The Launcher creates app.pyv2, index.html, runner.js, an offline copy of pyv2.js, and ready-to-run .vscode tasks/settings.
  3. Edit app.pyv2. Its output becomes the website title, tagline, and feature list.
  4. Choose local preview. The Launcher starts a safe local HTTP server on an available port and opens your browser.
# app.pyv2
site_name = "My first Python v2 website"
print(site_name)
print("Built from a real .pyv2 program")
for feature in ["Fast", "Offline", "Mine"]:
    print(feature)
end

06 PyHope Game Engine

PyHope is Python v2's own dependency-free game engine. It is not pygame and it installs no native libraries. The portable Python module handles game logic and terminal previews; the website adds Canvas and WebGL2 renderers for full visual games.

Install and verify

# one-click: download install.bat (Windows) or install.sh (macOS/Linux)
# manual, from the cloned repo:
python3 -m pip install --user .

pyv2 --version
pyhope --check
pyhope --demo

Download the installers. The installer adds both commands and runs the check automatically.

Core API

SpriteNamed entity with position, velocity, tags and alive stateSprite("hero", Vec2(2, 2), "@")

Your first PyHope scene

from pyhope import Engine, Sprite, TileMap, Vec2

world = TileMap.from_text("""#####
#...#
#...#
#####""")
engine = Engine(world)
hero = engine.add(Sprite("hero", Vec2(1.5, 1.5), "@"))
hero.velocity = Vec2(0.5, 0)
engine.step()
print(engine.render_ascii())

The visual examples are open source: game.js is the CPU sprite raycaster, gpu-game.js is the 9M renderer, and games.js contains Comet Hopper. Original sprites are CC0 in assets/sprites/.
